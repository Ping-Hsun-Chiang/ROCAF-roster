# EXP-004：以統計檢定驗證公平性（對照組）

- **日期：** 2026-10-25
- **結果：** ✅ 驗證通過；另有一項 🔍 待觀察的小偏差
- **對應 commit：** 新增本檔案的 commit（`git log -- docs/experiments/EXP-004-statistical-validation.md`）

## 動機

EXP-001～003 只用描述統計（最小值、最大值、SD），且 seed 數只有 1～5 個，無法回答兩個問題：

1. 「公平」是演算法的功勞，還是硬性規定本身就會讓結果自然平均？
2. 觀察到的改進是真的，還是剛好遇到比較好的亂數？

## 假設

- **H1：** 現行演算法的月結算偏差顯著小於「只守硬性規定、隨機排人」的對照組。
- **H2：** 現行演算法沒有「某些人系統性被多排或少排」的現象
  （chi-square goodness-of-fit test 不拒絕「依上班天數比例分配」）。
- **H3：** 哨長與僅槍兵每上班天的負擔沒有系統性差異。

## 方法

- **工具：** `npm run simulate`（報告）、`npm run simulate -- --ablation`（消融實驗），**30 seeds**。
- **對照組（control group）：** `randomOrder: true`，每次決策都以 Fisher-Yates 洗牌決定候選人順序，
  只遵守硬性規定。與現行版本使用**完全相同的出勤資料**（出勤由情境 seed 決定，與演算法無關）。
- **指標與檢定：**
  - 偏差 RMS：每人「實際節數 − 應得節數」的 root mean square。
  - Gini coefficient：每人「節數／上班天」的不均程度。
  - Chi-square goodness-of-fit test 與 dispersion index（χ²／df，純隨機抽籤約為 1）。
  - Mann-Whitney U test：比較兩個版本在 30 個 seed 下的偏差 RMS。
  - 95% confidence interval。
- 結構性人力不足的情境（S4、S5、S6）不參與公平性比較，只檢查規定與空缺。

## 結果

完整表格見 [`../simulation-report.md`](../simulation-report.md) 與 [`results/ablation.md`](results/ablation.md)。

### 硬性規定

12 個情境 × 30 seeds，獨立 checker 找到的違規數：**0**。

### H1：現行版本 vs 對照組（9 個非結構性情境）

| 指標 | 現行版本 | 對照組 |
| --- | --- | --- |
| 偏差 RMS（節） | 0.36～0.68 | 3.31～7.66 |
| Gini | 0.003～0.016 | 0.051～0.239 |
| Dispersion index | 0.00～0.02 | 0.33～2.58 |
| 灰色偏差 RMS（節） | 0.32～0.78 | 2.52～3.25 |

所有情境的 Mann-Whitney p < 0.001。**H1 成立**：偏差約為對照組的 1/10 到 1/20。

對照組的 dispersion index 在多數情境 > 1，代表「只守規定、隨機排人」比純抽籤還不平均：
隨機排序容易讓同一人一天站滿 3 班。現行版本的 dispersion index 接近 0，
代表分配遠比隨機抽籤平均，這正是排班演算法要達成的效果。

### H2：系統性偏差

9 個情境中，χ² 上尾檢定 p ≥ 0.05 的 run 比例皆為 **100%**。**H2 成立**：沒有證據顯示有人被系統性多排或少排。

### H3：哨長 vs 僅槍兵（🔍 小偏差）

| 情境 | 哨長÷僅槍兵 | Mann-Whitney p |
| --- | --- | --- |
| S1 標準單位 | 1.001 | 0.630 |
| S3 大單位 | 1.006 | < 0.001 |
| S9 長假 | 1.006 | < 0.001 |
| S10 中途報到／離營 | 1.019 | < 0.001 |
| 其他 4 個情境 | 0.999～1.008 | 0.06～0.19 |

S3、S9、S10 的差異達統計顯著，**H3 部分不成立**：哨長的負擔系統性地略高。
但效果量（effect size）很小：S10 最大，約 1.9%，相當於每月多約 0.6 節。
樣本是 30 seeds × 每情境約 25 人，數量大，因此很小的差異也會被判定為顯著。

可能原因：哨長兩種位置都能站，可排入的機會比僅槍兵多，在公平值相同時更容易被選中。

### 消融實驗：重新驗證 EXP-001、EXP-002（30 seeds）

| 移除的改進 | 偏差 RMS | 灰色偏差 RMS | 空缺 |
| --- | --- | --- | --- |
| 灰色公平值（EXP-001） | 現行略差 0.01～0.09 節；S3、S9、S10 顯著（p < 0.05） | 現行 0.32～0.78 vs 移除後 1.37～2.27，全部 p < 0.001 | S2：現行 2.2 vs 移除後 1.2 格 |
| Jitter 單位修正（EXP-002） | 現行 0.36～0.68 vs 移除後 0.79～0.91，全部 p < 0.001 | 現行略好，9 個情境中 8 個 p < 0.05 | 無差異 |

- **EXP-001 的 trade-off 被確認：** 灰色公平值大幅改善灰色時段的分配（偏差約降為 1/3～1/6），
  代價是總節數偏差略增（最多 0.09 節），且小單位的空缺增加約 1 格／月。
- **EXP-002 被確認：** 所有情境都顯著改善，沒有觀察到代價。

## 結論與後續

- H1、H2 成立，可以有根據地說「這套排法是公平的」，而不只是「看起來平均」。
- H3 有統計顯著但實務上可忽略的偏差（< 2%），先記錄為待觀察。
  可能的後續實驗：在候選人排序中，對「可排入多種位置的人」加入極小的補償。
- 運算時間：最慢的情境（S6 哨長稀缺）單日最多約 0.4 秒。
- 公平性門檻已寫入 CI（`npm run simulate -- --check`），每次 push 都會自動驗證。
